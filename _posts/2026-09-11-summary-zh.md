## [OpenAI 发布 Agents API，支持自托管沙箱](https://developers.openai.com/api/docs/guides/agents-api/overview) ⭐️ 8.0/10

OpenAI 发布了 Agents API，开发者只需一次 API 调用，指定任务、模型、工具和环境，即可构建并部署生产级智能体应用。该 API 运行 Codex harness 并管理底层智能体基础设施，同时提供可选的 自托管沙箱 用于工具执行。 这是平台级举措，将 OpenAI 定位为智能体应用的默认基础设施提供商，可能重塑开发者构建 AI 智能体的方式，并加剧与 Anthropic 托管智能体服务的竞争。同时，它也引发了关于供应商锁定、抽象设计以及原始 LLM 端点与完整智能体 harness 之间界限模糊的重要问题。 该 API 围绕四个概念构建：Agent（模型、指令、工具、MCP 服务器）、Environment（可选的沙箱或计算机，用于访问文件、加载技能和执行命令）、Session（持久化的智能体实例）以及 Events/items（输入与输出）。它包含自动上下文压缩、多智能体编排、程序化工具调用和 MCP 支持，默认由 OpenAI 托管和维护 harness。

hackernews · aquir · 9月10日 19:43 · [社区讨论](https://news.ycombinator.com/item?id=49649213)

**背景**: 智能体应用（agentic applications）是构建在自主智能体基础设施之上的软件程序，利用 AI 智能体来理解和执行复杂任务。构建智能体 harness——即管理工具、状态和执行流程的编排层——是一项极其复杂的工程，而 OpenAI 的 Agents API 旨在将这一层抽象掉。自托管沙箱允许开发者将工具执行和敏感数据保留在自己的基础设施中，同时由供应商管理编排。

## [Forgejo 16.0.4 修复模板仓库中的严重 RCE 漏洞](https://codeberg.org/forgejo/forgejo/src/branch/forgejo/release-notes-published/16.0.4.md) ⭐️ 8.0/10

Forgejo 发布了 16.0.4 和 15.0.8 版本，修复了一个严重的远程代码执行漏洞（CVE-2026-89094），该漏洞影响 16.0.4 之前的所有版本，问题出在从模板仓库初始化新仓库时对 .forgejo/template 目录下文件的模板展开处理不当。 这是广泛使用的自托管 Git 服务中的一个严重 RCE 漏洞，任何运行未修补版本的实例都可能被能够创建或提供恶意模板仓库的攻击者攻破，可能导致服务器被完全接管。 该漏洞的成因是 Forgejo 在从模板仓库生成新仓库时，会克隆模板仓库、删除 .git 文件夹、对 .forgejo/template 中列出的文件执行变量模板展开，然后初始化新的 git 仓库；模板展开处理不当导致可执行任意代码。修复已包含在 16.0.4 和 15.0.8 中，该漏洞被分配为 CVE-2026-89094。

hackernews · weierstass · 9月10日 15:57 · [社区讨论](https://news.ycombinator.com/item?id=49645907)

**背景**: Forgejo 是 Gitea 的社区驱动分支，Gitea 是一个类似 GitHub 的轻量级自托管 Git 服务。模板仓库允许用户通过复制预定义的仓库结构并替换变量来快速搭建新项目。由于该过程在仓库创建时于服务端执行，模板展开处理不当可能让攻击者在服务器上注入并执行代码。

## [微软将 Rust 列为一级语言](https://rustfoundation.org/media/guest-post-rust-is-tier-1-language-at-microsoft/) ⭐️ 8.0/10

微软已正式将 Rust 列为一级（Tier-1）语言，使其与 C++、C# 和 TypeScript 并列成为公司支持力度最大的规范语言之一。这一消息通过 Rust 基金会的客座文章发布，意味着内部团队现在拥有一条从本地开发到生产部署的完整 Rust 路径，涵盖安全工具链构建、开发者工具、质量工作流，以及对微软安全开发生命周期（SDL）要求的合规。 这是一个重要的行业里程碑，标志着 Rust 已从快速迭代的新兴语言转变为获得企业长期支持的成熟主流系统编程语言。这也意味着所有在 C 和 C++ 工具链中占有一席之地的主流操作系统厂商，如今都在新项目开发中实现了系统编程语言的多元化，这可能加速 Rust 在整个软件生态中的普及。 微软的一级语言地位是一项工程认定，为内部团队提供从本地开发到生产部署的受支持路径，包括安全工具链构建、高效的开发者工具、质量工作流、深度平台集成以及 SDL 合规。值得注意的是，经过数十年的发展，C++ 在微软代码库中仍占据主导地位；此外，这一公告还带来了关于传闻已久的 Rust 与 MSVC 集成的公开消息。

Farid Zakaria 发布了 trynix.dev，他称其为自己在 Nix 领域的“代表作”（magnum opus）。该项目利用 qemu-wasm 在浏览器内完整运行一个 x86_64 Linux 虚拟机，并能启动过去 13 年中的任意 Nix 包。这些包可通过 URL 直接寻址，例如访问 https://trynix.dev/?pkg=python3%403.6.2 并点击“Load”，即可获得一个运行 2017 年 Python 3.6.2 的交互式 shell。他还发布了 trynix-preview，这是一个 GitHub Action，会在 Pull Request 下评论一个链接，让评审者无需服务器即可在浏览器中启动该 PR 的构建。 这让可复现的软件环境可以像普通网址一样被即时分享，对软件考古、调试旧构建以及通过实际启动来评审 Pull Request（而非静态推理）都具有重要意义。由于一切都在客户端通过 WebAssembly 运行，它降低了复现历史环境的门槛，无需安装 Nix、QEMU 或任何服务器基础设施。 该虚拟机由 ktock/qemu-wasm 驱动，它把 QEMU 的翻译块（TB）转换为 WebAssembly 模块，并借助 WebAssembly.Module 和 WebAssembly.Instance 等浏览器 API 来执行，因为 Wasm 无法将控制权转移到内存中生成的代码。项目覆盖过去 13 年的 Nix 包，并支持 URL 寻址，不过在浏览器中运行完整虚拟机意味着相比原生执行存在性能和资源方面的限制。
